# 1001-智能体记忆

## 1. 背景与目标

### 1.1 背景
在电商AI导购场景中，智能体需要理解用户的上下文对话和历史偏好，才能提供精准的个性化推荐。当前系统缺乏记忆机制，导致：
- 用户每次对话都需要重复说明需求，体验割裂
- 无法基于历史对话理解用户意图（如"这件衣服适合参加晚宴吗"需要上下文）
- 无法积累用户偏好，个性化推荐能力受限

### 1.2 目标
- **用户价值**：提升对话连贯性，减少重复沟通，获得更精准的个性化推荐
- **业务价值**：提高用户满意度，增强用户粘性，提升转化率
- **技术目标**：建立完整的记忆体系，支持短期上下文记忆和长期用户画像沉淀

### 1.3 成功指标
- 用户重复说明需求的次数降低 ≥30%
- 对话上下文理解准确率 ≥85%
- 用户画像更新覆盖率 ≥90%
- 对话响应时间增加 <200ms（相比无记忆机制）

## 2. 功能详述

### 2.1 短期记忆

#### 2.1.1 功能概述
短期记忆用于记录当前对话会话内的完整交互内容，帮助智能体理解上下文，实现连贯对话。

#### 2.1.2 用户故事
**作为** 用户  
**我希望** 智能体能记住我在当前对话中提到的所有信息  
**以便于** 后续对话中无需重复说明，获得更精准的推荐

#### 2.1.3 业务规则
1. **记录范围**：在同一token（会话）内，全量记录用户与智能体的所有交互内容
   - 用户输入：问题、指令、反馈等
   - 智能体输出：回答、推荐、建议等
   - 交互元数据：时间戳、消息类型等

2. **用户隔离**：短期记忆与当前用户ID严格绑定
   - 不同用户之间的记忆完全隔离，互不影响
   - 同一用户在不同设备/会话中的记忆独立管理

3. **生命周期**：
   - 创建时机：用户开启新对话时创建新的短期记忆实例
   - 销毁时机：对话结束或超时后，短期记忆可归档或清除
   - 超时规则：建议30分钟无交互后自动结束会话

4. **容量限制**：
   - Token限制：单次对话的短期记忆不超过模型最大上下文窗口的80%
   - 消息条数限制：建议不超过50轮对话（可根据实际调整）

#### 2.1.4 交互流程
```
用户发起对话
  ↓
系统检查是否存在活跃的短期记忆
  ↓
[存在] → 加载历史对话记录 → 合并到当前上下文
  ↓
[不存在] → 创建新的短期记忆实例
  ↓
用户输入 → 记录到短期记忆 → 智能体处理（携带完整上下文）
  ↓
智能体响应 → 记录到短期记忆 → 返回给用户
  ↓
循环上述过程，直到对话结束
```

#### 2.1.5 数据逻辑
- **存储结构**：
  ```
  {
    "session_id": "会话唯一标识",
    "user_id": "用户ID",
    "messages": [
      {
        "role": "user|assistant",
        "content": "消息内容",
        "timestamp": "时间戳",
        "message_id": "消息ID"
      }
    ],
    "created_at": "创建时间",
    "updated_at": "最后更新时间",
    "expires_at": "过期时间"
  }
  ```

- **查询逻辑**：根据user_id和session_id查询短期记忆，按时间戳排序

### 2.2 长期记忆（用户画像）

#### 2.2.1 功能概述
长期记忆通过用户画像的形式沉淀用户偏好、行为特征等信息，在对话开启时自动加载，实现跨会话的个性化服务。

#### 2.2.2 用户故事
**作为** 用户  
**我希望** 智能体能记住我的偏好和历史行为  
**以便于** 每次对话都能获得符合我喜好的个性化推荐

#### 2.2.3 业务规则
1. **更新时机**：
   - 每完成一轮对话（一次接口调用）后，通过智能体Tool触发用户画像更新
   - 更新为增量更新，保留历史信息，仅更新变化部分

2. **加载时机**：
   - 智能体开启新对话时，自动从Tool中获取用户画像
   - 将用户画像信息格式化后，加入到短期记忆的初始上下文中

3. **画像内容**（示例）：
   - 基础信息：年龄、性别、身材特征等
   - 偏好信息：风格偏好、颜色偏好、品牌偏好等
   - 行为信息：浏览历史、购买历史、反馈记录等
   - 场景信息：常用场景（如：工作、晚宴、日常等）

4. **隐私保护**：
   - 用户可查看、编辑、删除自己的用户画像
   - 遵循数据隐私法规，支持数据导出和删除

#### 2.2.4 交互流程
```
对话开始
  ↓
检查是否为开启新对话
  ↓
[是] → 调用Tool获取用户画像 → 格式化画像信息 → 加入短期记忆初始上下文
  ↓
[否] → 继续使用当前短期记忆
  ↓
对话进行中...
  ↓
对话结束（一轮接口调用完成）
  ↓
智能体Tool分析对话内容，提取用户信息
  ↓
增量更新用户画像
  ↓
保存更新后的用户画像
```

#### 2.2.5 数据逻辑
- **存储结构**：
  ```
  {
    "user_id": "用户ID",
    "profile": {
      "basic_info": {
        "age": "年龄区间",
        "gender": "性别",
        "body_type": "身材类型"
      },
      "preferences": {
        "style": ["风格1", "风格2"],
        "colors": ["颜色1", "颜色2"],
        "brands": ["品牌1", "品牌2"]
      },
      "behavior": {
        "browse_history": [],
        "purchase_history": [],
        "feedback": []
      },
      "scenarios": ["场景1", "场景2"]
    },
    "updated_at": "最后更新时间",
    "version": "画像版本号"
  }
  ```

- **更新策略**：
  - 使用版本号机制，支持画像回滚
  - 关键信息变更时记录变更日志
  - 定期清理过期或无效的画像数据

### 2.3 对话管理

#### 2.3.1 开启对话
**定义**：开启新对话是指创建新的对话会话，清空或初始化短期记忆。

**判断条件**：
1. **自动判断**：获取短期记忆为空时，代表开启新的对话
2. **强制开启**：通过请求入参（如 `force_new_session=true`）强制开启新的对话

**触发场景**：
- 用户首次使用
- 用户主动点击"新对话"
- 会话超时后重新开始
- 用户切换设备或清除缓存

#### 2.3.2 结束对话
**定义**：对话会话结束，短期记忆归档或清除。

**触发条件**：
- 用户主动结束对话
- 会话超时（建议30分钟无交互）
- 达到对话轮数上限
- 用户登出

## 3. 非功能需求

### 3.1 性能要求
- 短期记忆加载时间：<100ms（P95）
- 用户画像加载时间：<200ms（P95）
- 记忆写入延迟：<50ms（P95）
- 支持并发用户数：≥10000

### 3.2 可用性要求
- 系统可用性：≥99.9%
- 数据持久化：记忆数据需持久化存储，支持故障恢复
- 降级策略：当记忆服务不可用时，系统应能降级为无记忆模式继续服务

### 3.3 安全要求
- 数据隔离：严格保证用户数据隔离，防止数据泄露
- 访问控制：用户只能访问自己的记忆数据
- 数据加密：敏感数据需加密存储和传输
- 审计日志：记录关键操作日志，支持审计追踪

### 3.4 扩展性要求
- 支持记忆数据的水平扩展
- 支持不同存储后端（Redis、数据库等）
- 支持记忆数据的导入导出
- 预留接口支持未来扩展更多记忆类型

## 4. 异常处理

### 4.1 短期记忆异常
- **记忆丢失**：如果短期记忆查询失败，记录错误日志，创建新的记忆实例继续服务
- **容量超限**：当记忆容量接近上限时，采用LRU策略清理早期消息，保留最近N轮对话
- **并发冲突**：使用乐观锁或分布式锁保证并发安全

### 4.2 用户画像异常
- **画像获取失败**：如果用户画像获取失败，记录错误日志，使用默认画像或空画像继续服务
- **画像更新失败**：如果画像更新失败，记录错误日志，下次对话时重试更新
- **数据不一致**：定期校验画像数据一致性，发现异常时触发修复流程

### 4.3 系统异常
- **服务不可用**：当记忆服务完全不可用时，系统降级为无记忆模式，保证核心功能可用
- **数据损坏**：检测到数据损坏时，尝试从备份恢复，无法恢复时创建新实例

## 5. 名词解释

- **短期记忆**：记录当前对话会话内的完整交互内容，用于理解上下文
- **长期记忆（用户画像）**：跨会话存储的用户偏好和行为特征信息
- **开启对话**：创建新的对话会话，初始化短期记忆
- **Token**：在此文档中指代一个完整的对话会话周期
- **Tool**：智能体提供的工具接口，用于获取和更新用户画像
- **会话超时**：用户无交互达到指定时间后，自动结束当前会话

## 6. 后续优化方向

1. **记忆压缩**：对长期对话进行智能压缩，保留关键信息
2. **多模态记忆**：支持图片、视频等多模态内容的记忆
3. **记忆搜索**：支持用户搜索历史对话内容
4. **记忆分享**：支持用户导出或分享对话记录
5. **个性化记忆策略**：根据用户行为动态调整记忆策略和容量
