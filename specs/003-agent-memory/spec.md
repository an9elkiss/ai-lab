## Clarifications

### Session 2026-01-07

- Q: 跨session的记忆范围是什么？→ A: 跨session不需要记住聊天上下文，只需在聊天开始时提供用户画像（长期记忆）。聊天上下文只需要在同一个session中保持，比如半小时内。
- Q: 系统如何识别同一用户跨session的身份？→ A: 使用用户认证系统（登录/注册），每个用户有唯一账户。
- Q: 系统何时将对话信息提取并保存到长期记忆？→ A: 实时提取：用户每次表达偏好或事实时立即保存到长期记忆。
- Q: 当用户提供冲突信息时，系统应该如何处理？→ A: 保留两者：将冲突信息都保存，标记时间戳，让用户后续选择。
- Q: 单个用户的长期记忆应该有存储上限吗？→ A: 设置上限（如1000条记忆项），超出时自动清理最旧/最不重要的项。
- Q: 系统如何评估记忆项的重要性？→ A: 仅基于时间：最旧的记忆项优先被清理。
- Q: 是否提供用户主动清除记忆的功能？→ A: 不提供此功能。用户无法主动清除记忆。记忆由系统管理。
- Q: session内的记忆如何处理？→ A: 在同一session中记忆无需查找，智能体会保存当前session的完整记忆。
- Q: 长期记忆如何加载？→ A: 长期记忆等同于用户画像，在session开始时全量加载。
- Q: 用户画像何时更新？→ A: 用户画像是在完成与智能体的一次交互时由系统提炼的。一次交互 = 一问一答（调用一次智能体接口）。
- Q: 用户画像更新时如何处理矛盾信息？→ A: 如果存在矛盾的信息，将保留session中的最新特征。
- Q: 长期记忆如何实现？→ A: 长期记忆等同于用户画像，长期记忆的维护通过LangChain4j的Tool来提供。
- Q: 短期记忆如何实现？→ A: 短期记忆由LangChain4j框架以组件方式提供，不通过实体方式维护。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Cross-Session Continuity (Priority: P1)

作为用户（销售人员或客户），我希望智能体能够在新的会话开始时记住我的用户画像（长期偏好和关键信息），这样我就不需要重复已经提供过的信息。

**Why this priority**: 无缝连续性是一个"智能"智能体与简单聊天机器人的主要区别。它直接影响用户效率和满意度。

**Independent Test**: 可以通过模拟两个不同的会话来测试。在会话1中，提供特定的用户偏好（如预算、产品类型）。在会话2中，验证智能体在会话开始时加载了这些用户画像信息。

**Acceptance Scenarios**:

1. **Given** 用户在会话A中之前声明他们的预算是"低于5万美元"，**When** 他们开始会话B并询问"给我推荐"，**Then** 智能体基于5万美元的预算过滤结果，无需提醒（用户画像在会话开始时已加载）。
2. **Given** 用户在会话A中表达了偏好"SUV"，**When** 他们开始会话B并询问"有什么推荐吗？"，**Then** 智能体基于已加载的用户画像推荐SUV相关产品。

---

### User Story 2 - Automatic Preference Learning (Priority: P1)

作为用户，我希望智能体能够在每次交互后自动学习和更新我的偏好，以便未来的推荐越来越个性化，而无需我主动操作。

**Why this priority**: 允许智能体随着时间的推移不断改进，并展示主动倾听的能力，同时保持用户体验的简洁性。

**Independent Test**: 在一次交互中表达偏好（例如，"我不喜欢红色"），验证在该交互完成后用户画像已自动更新，并在后续会话中生效。

**Acceptance Scenarios**:

1. **Given** 智能体建议了一个红色物品，**When** 用户说"我不喜欢红色"并完成该次交互，**Then** 系统自动更新用户画像，在当前和未来的会话中停止建议红色物品。
2. **Given** 存储了"SUV"的偏好，**When** 用户在一次交互中说"实际上，我现在在找轿车"，**Then** 系统在该交互完成后自动将偏好更新为"轿车"，并在后续推荐中生效。


### Edge Cases

- **Conflicting Information**: 如果用户在session中提供矛盾的信息（例如，"我是素食主义者"然后又说"我喜欢牛排"），系统在更新用户画像时保留session中的最新特征，覆盖之前的矛盾信息。
- **Sensitive Data (PII)**: 智能体应检测高敏感度的个人身份信息（如信用卡号），并严格避免将其提交到长期持久化记忆中，或对其进行掩码处理。
- **Ambiguous References**: 当用户说"我喜欢那个"，但"那个"在上下文中不清楚时，智能体必须要求澄清，而不是猜测并存储可能不正确的偏好。
- **Memory Saturation**: 如果对话非常长，智能体必须总结较旧的上下文，以保持在处理限制内，同时不丢失关键事实。当长期记忆达到存储上限时，系统按时间顺序自动清理最旧的记忆项。
- **Session Timeout**: 聊天上下文仅在同一个session内保持（约30分钟）。超过session超时时间后，上下文不再可用，但用户画像（长期记忆）仍然保留。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在每次完成与智能体的交互后（一问一答完成后）从对话中提取结构化事实（如预算、产品类型、颜色等实体），并通过Tool接口更新长期记忆（用户画像）。
- **FR-002**: 系统必须要求用户通过认证系统（登录/注册）建立唯一账户，并通过Tool接口将用户画像信息持久化到与唯一用户ID关联的长期记忆存储中，在新会话开始时通过Tool接口全量加载完整的用户画像。
- **FR-003**: 系统必须依赖LangChain4j框架组件维护完整的聊天上下文（短期记忆），智能体可直接访问当前session内的所有对话历史，该上下文仅在当前session内有效（约30分钟超时）。
- **FR-004**: 系统必须在session开始时全量加载用户的长期记忆（用户画像），session期间智能体直接访问已加载的用户画像和完整的会话上下文，无需进行记忆检索。
- **FR-005**: 系统不提供用户主动操作记忆的功能，所有记忆管理（包括保存、更新、删除）均由系统自动完成。
- **FR-006**: 系统必须强制执行隐私边界；用户只能访问/修改自己的记忆数据。系统必须通过用户认证确保用户身份验证，防止未授权访问。
- **FR-007**: 系统必须在用户画像更新时处理冲突信息，保留session中的最新特征，覆盖旧的矛盾信息（例如，预算从"5万美元"更新为"10万美元"时，直接覆盖旧值）。
- **FR-008**: 系统必须区分长期记忆（用户画像，跨session保持）和短期记忆（聊天上下文，仅session内保持）。
- **FR-009**: 系统必须通过LangChain4j Tool接口限制单个用户的长期记忆存储量（用户画像大小），当存储量超出限制时，Tool自动清理最旧的信息，确保加载性能。
- **FR-010**: 系统必须提供MemoryTool作为LangChain4j Tool，供智能体调用以维护用户画像。

### Key Entities

- **UserProfile**: 表示用户画像（等同于长期记忆），通过LangChain4j Tool接口进行维护。
  - `userId`: 用户唯一标识符
  - `facts`: 用户相关的事实信息（如预算、联系方式等）
  - `preferences`: 用户偏好信息（如产品类型、颜色偏好等）
  - `lastUpdated`: 最后更新时间
  - `version`: 画像版本号

## Integration Requirements *(mandatory)*

### LangChain4j Integration

- **短期记忆（聊天上下文）**: 由LangChain4j框架组件自动维护
  - 框架自动管理会话内的对话历史
  - 支持约30分钟的会话超时机制
  - 智能体可直接访问当前session的完整对话上下文
  - 无需自定义实体或存储逻辑

- **MemoryTool**: 作为LangChain4j Tool提供长期记忆（用户画像）维护功能。
  - `loadUserProfile(userId)`: 加载指定用户的完整画像
  - `updateUserProfile(userId, updates)`: 更新用户画像的特定字段
  - `extractProfileUpdates(interaction)`: 从用户交互中提取画像更新信息
  - Tool必须支持LangChain4j的标准Tool接口规范
  - Tool调用必须在每次交互完成后自动触发

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: **Recall Accuracy**: 在50个多轮对话的测试集中，智能体在>90%的情况下正确检索相关上下文/事实。
- **SC-002**: **Latency Impact**: 记忆检索和注入为总响应生成时间增加的时间少于200毫秒（不包括LLM推理时间）。
- **SC-003**: **System Memory Management**: 系统自动管理记忆存储，当达到1000条记忆项上限时，100%按时间顺序清理最旧记忆项。
- **SC-004**: **User Correction Rate**: 用户需要纠正智能体的回忆（例如，"不，我说的是X，不是Y"）的情况少于涉及过去上下文的交互的5%。
